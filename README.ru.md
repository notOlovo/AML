«AML transaction monitoring: triage and red-flag escalation»**

Английский [README.md](README.md) остаётся основным для жюри (сабмит и демо на английском). Этот файл для

## Коротко, за минуту

Проблема: в AML-мониторинге почти все алерты ложные, аналитики тонут в шуме.

Что делаем: берём весь синтетический поток ČNB (около 400 тыс. платежей, 5 500 клиентов) и превращаем его в
короткую ранжированную очередь дел по клиентам. Каждое дело объяснено цифрами, которые аналитик (а потом и
регулятор) может проверить построчно. Claude пишет текст дела и черновик STR (сообщения о подозрительной
операции), но отдельный верификатор сверяет каждую его цифру с данными, а решение всегда принимает человек.

Слоган для питча: **правила находят, Claude объясняет, верификатор проверяет, человек решает.**

```
transactions.csv ─┐                          ┌─ очередь дел (1 дело на клиента), по убыванию риска
clients.csv ──────┼─► 10 AML-типологий ─────►│   балл = сумма баллов правил × множитель риска клиента
Mostly Right ─────┘   (pandas, ~15 с/400k)   │   фильтр подтверждения: один слабый сигнал не открывает дело
                                              └─► только топ дел ─► пакет доказательств (E1..En + транзакции)
                                                                      │
                                          Claude 4.5 на Bedrock ◄─────┘  (или бесплатный шаблон без LLM)
                                                 │
                               проверка цифр и ссылок ─► решение аналитика + причина ─► журнал аудита
                                                 └─► черновик STR для MLRO (§18 закона 253/2008 Sb.)
```

## Почему это не «обёртка над GPT»

- **Обнаружение детерминированное и объяснимое.** 10 AML-типологий: дробление сумм под порогом
  (structuring), транзит денег через счёт (денежный мул), отклонение от заявленного профиля (ожидаемый и
  фактический объём и число операций за 2Q2026), скрининг контрагентов по спискам, высокорисковые
  юрисдикции, рискованные MCC (казино, крипта, денежные переводы), внезапная активность спящего счёта,
  большие обороты на новом счёте, всплеск числа операций, круглые суммы. Каждое правило срабатывает с
  конкретными фактами и ID транзакций. LLM не решает, кто подозрительный.
- **Снижение шума встроено.** Срабатывания сводятся в одно дело на клиента, одиночные слабые сигналы
  подавляются, а комплаенс-офицер ползунками выбирает баланс между размером очереди и покрытием и видит
  кривую в реальном времени.
- **LLM в рамках.** Модель видит только пакет доказательств, обязана ссылаться на их ID (E1, E2…), а
  верификатор помечает любую сумму, количество или дату, которой нет в данных. Если Bedrock недоступен или
  кончился бюджет, текст собирается по шаблону, так что демо не сломается.
- **Дёшево.** Объясняются только топовые дела (Haiku 4.5 для черновиков, Sonnet 4.5 для финального текста),
  системный промпт кэшируется, ответы сохраняются на диск. По ценам из гайда AWS 20 дел через Sonnet стоят
  около USD 0,5 (это оценка, на реальных вызовах ещё не проверяли). Текущие траты видны в интерфейсе.

## Как запустить

```bash
pip install -r requirements.txt
python -m amlcopilot.cli generate --out data/sample      # синтетика с подсаженными схемами
streamlit run app.py                                     # интерфейс на http://localhost:8501
python -m pytest                                         # 11 тестов, ~5 с
```

### В контейнере (Podman или Docker)

```bash
# сначала положить clients.csv и transactions.csv в data/real/
scripts/run_container.sh            # для Docker: ENGINE=docker scripts/run_container.sh
# открыть http://localhost:8501
```

### На реальных данных ČNB (аккаунт команды в AWS)

```bash
aws sso login --profile hackathon
export AWS_PROFILE=hackathon AWS_REGION=eu-central-1
scripts/fetch_data.sh                                    # копирует CNB/ и MostlyRIght/ в data/real/
python -m amlcopilot.cli inspect --data data/real        # сначала проверить сопоставление колонок
python -m amlcopilot.cli run --data data/real --top 20 --llm haiku
AML_DATA=data/real streamlit run app.py
```

Загрузчик находит колонки по ключевым словам (английским и чешским), понимает UTF-8 BOM, точку с запятой и
десятичную запятую. Если нужной колонки нет, соответствующее правило отключается, а не падает. Названия
колонок реальных файлов мы заранее не знали, поэтому **первым делом запускаем `inspect`**. Если колонка
сопоставилась неправильно, исправляем в JSON и передаём `--column-map map.json`:

```json
{"transactions": {"amount": "Amount CZK"}, "clients": {"exp_volume": "Expected volume 2Q2026"}}
```

## Что видит аналитик

1. **Очередь (Triage queue):** транзакции → сырые срабатывания правил → дела, по убыванию балла, с
   типологиями, рейтингом AML-риска и флагом PEP.
2. **Дело (Case):** вклад каждого доказательства в балл, таймлайн операций клиента (подозрительные красным),
   текст с бейджем проверки цифр, смягчающие факторы, вопросы клиенту, правовое основание и черновик STR
   одной кнопкой.
3. **Решение:** эскалировать MLRO, запросить информацию или закрыть как ложное срабатывание, с обязательной
   причиной. Каждое решение пишется в журнал вместе с хэшем настроек правил, хэшем доказательств, моделью и
   отметкой, переспорил ли человек рекомендацию AI.
4. **Настройка (Tuning):** кривая «число дел от порога», а на синтетике ещё полнота и точность по каждой
   типологии.

## Результаты на данных ČNB

5 493 клиента, 397 853 транзакции за июль 2026, плюс история каждого клиента за 2Q2026 в `clients.csv`.
Весь прогон занимает около 10 секунд:

- 407 срабатываний правил на 382 клиентах превращаются в **21 дело (0,4% клиентов)**, из них 1 на немедленную
  эскалацию.
- Все тексты дел проходят проверку цифр.
- Чего в данных нет: кодов MCC и имён контрагентов, поэтому правила рискованных MCC и скрининга по спискам сами
  отключаются. Контрагентов из высокорисковых стран по списку ЕС нет, так что правило по юрисдикциям ничего не
  находит. Суммы распределены одинаково во всех валютах, поэтому считаем их уже пересчитанными в кроны.
- Что в данных есть, это история клиента, и мы добавили под неё правило: июль сравнивается не только с
  объёмом, заявленным при открытии счёта, но и с собственным темпом клиента за 2Q2026 и его крупнейшим платежом
  за 2Q2026. Отношения нормируем на типичного клиента, потому что типичный клиент и так превышает заявленный
  объём примерно в 2 раза.

Разметки в данных ČNB нет, поэтому точность на них неизвестна. На нашей синтетике с подсаженными случаями
(1 200 клиентов, 83 тыс. транзакций, 60 случаев) находится 95% подсаженных случаев, и 76% дел настоящие.

## Структура проекта

| Путь | Что там |
|---|---|
| `amlcopilot/schema.py` | загрузчик и сопоставление колонок |
| `amlcopilot/typologies.py` | 10 правил и их настройки (пороги, веса) |
| `amlcopilot/scoring.py` | сведение в дела, фильтр подтверждения, ранжирование, оценка качества |
| `amlcopilot/screening.py` | скрининг контрагентов по предупреждениям и санкциям Mostly Right |
| `amlcopilot/explain.py` | пакет доказательств, шаблонный текст и текст Claude, верификатор, черновик STR, учёт трат |
| `amlcopilot/audit.py` | журнал решений (только дописывание) |
| `amlcopilot/synth.py` | генератор синтетики с подсаженными схемами |
| `app.py` | интерфейс аналитика на Streamlit |
| `docs/MODEL_CARD.md` | ответственный AI (на английском) |
| `docs/DEMO.md` | сценарий демо на 4 минуты (на английском) |

## Кто что может взять

- **Данные:** реальные файлы уже лежат в `data/real/` и подключены. Можно подкрутить пороги в
  `amlcopilot/typologies.py` (класс `Config`) или ползунками в интерфейсе.
- **AWS/LLM:** проверить вызов Bedrock (`--llm haiku`), посмотреть качество текстов, следить за бюджетом.
- **Комплаенс:** сходить на AML Crash Course (пн 13:30), сверить типологии и ссылки на законы с менторами
  FINREG PARTNERS / ČNB.
- **Питч:** отрепетировать `docs/DEMO.md`, подготовить ответы на Q&A.
